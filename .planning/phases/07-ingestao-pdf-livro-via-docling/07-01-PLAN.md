<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI args -> filesystem | `--slug` and `<pdf>` are user-controlled and become a write path under `.projetos/<slug>/livro/` |
| script -> markdownlint subprocess | a child process is spawned with `shell=True` on Windows |
| script -> docling -> Hugging Face | first-run model download is outbound only (no inbound untrusted data) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | `--slug` -> write path | mitigate | `sanitize_slug` rejects `..`, `/`, `\`, and anything outside `^[a-z0-9-]+$` BEFORE building out_dir; friendly `sys.exit`. Test `test_slug_rejected` (ASVS V5, slug convention `mentor/novo-projeto.md:107`). |
| T-07-02 | Injection (E) | markdownlint subprocess (`shell=True`) | mitigate | Args are a FIXED literal list `["markdownlint", "--fix", str(path)]` + a controlled path; NO user text is ever interpolated into a shell string. Path is the script-built `write_path`, not raw arg. |
| T-07-03 | Denial of Service | huge/malicious PDF -> OCR OOM | mitigate | `AcceleratorOptions(num_threads=1)` + OMP/MKL/OPENBLAS env guards bound memory; documented `page_range` batch fallback for OOM (Pitfall 1). Optionally pass docling `max_num_pages`/`max_file_size` if the real book trips it. |
| T-07-04 | Information Disclosure | writing outside the project dir | accept | Single-user local CLI; combined with T-07-01 slug whitelist the write stays under `.projetos/<slug>/livro/`. No multi-tenant data, no secrets. Low risk (ASVS V12). |

No HIGH-severity threats: local single-user CLI, no auth/network-input surface (RESEARCH Security Domain).
