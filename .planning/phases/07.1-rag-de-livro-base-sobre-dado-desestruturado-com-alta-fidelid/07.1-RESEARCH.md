### Pattern 2: Fronteira de capitulo por layout (D-04, corrige os 778 cacos)

**What:** Usar o histograma (ja impresso pelo script) + os labels do MinerU (`title`/`doc_title`
vs `text`) e tamanho de fonte (via `bbox` altura) para cortar SO em fronteira real.
**When:** Sempre que dividir em `*.md`; o chunking de retrieval e SEPARADO (D-04).

```python
# content_list.json: cada bloco tem type, page_idx, text, e (no middle.json) bbox.
# Heuristica deterministica: corte = bloco type in {"title"} OU heading cujo
# tamanho-de-fonte (altura do bbox) >= percentil do histograma. NAO LLM.
def is_chapter_boundary(block, font_cut_height):
    if block.get("type") == "title":
        return True
    h = bbox_height(block)              # do middle.json
    return block.get("text_level") == 1 or (h is not None and h >= font_cut_height)
```

### Pattern 3: Chunk parent-child com provenance (D-05)

```python
# Deterministico, puro-python sobre content_list.json (sem lib de chunking pesada).
def build_chunks(content_list, chapter_of, target_tokens=768, overlap=128):
    chunks = []
    for parent in group_by_section(content_list, chapter_of):   # secao-pai
        for child in window(parent["text_blocks"], target_tokens, overlap):
            chunks.append({
                "id": f"{parent['chapter']}-{child['n']}",
                "text": child["text"],
                "page": child["page_idx"] + 1,            # ancora <!-- page: N --> vira campo
                "chapter": parent["chapter"],
                "concept_hint": parent.get("heading", ""),
                "latex": child["equations_latex"],        # de blocos type=="equation"
                "page_image_path": child["page_image_path"],
                "parent_id": parent["id"],
            })
    return chunks   # 1 linha por chunk -> corpus.jsonl
```

### Pattern 4: Indice hibrido num unico .db (D-07) + fusao RRF

```python
# Source: bge-m3 (FlagEmbedding) + sqlite-vec vec0 + FTS5 [CITED: HF card; VERIFIED load_extension local]
import sqlite3, sqlite_vec
from FlagEmbedding import BGEM3FlagModel

model = BGEM3FlagModel("BAAI/bge-m3", use_fp16=False)   # CPU: fp16 OFF (HF card)

db = sqlite3.connect(str(index_dir / "vectors.db"))
db.enable_load_extension(True); sqlite_vec.load(db); db.enable_load_extension(False)
db.execute("CREATE VIRTUAL TABLE vec_chunks USING vec0(embedding float[1024])")
db.execute("CREATE VIRTUAL TABLE fts_chunks USING fts5(text, content='')")  # sparse/BM25

# indexacao:
out = model.encode(texts, return_dense=True, return_sparse=True)   # dense_vecs + lexical_weights
# insere dense_vecs em vec_chunks; insere text em fts_chunks (rowid = chunk_id)

# consulta hibrida + RRF (Reciprocal Rank Fusion):
def rrf(dense_ranked, sparse_ranked, k=60):
    scores = {}
    for rank, cid in enumerate(dense_ranked):  scores[cid] = scores.get(cid,0)+1/(k+rank)
    for rank, cid in enumerate(sparse_ranked): scores[cid] = scores.get(cid,0)+1/(k+rank)
    return sorted(scores, key=scores.get, reverse=True)
```

> Esparso: duas opcoes equivalentes (discricao D-Claude) -- (a) FTS5 (BM25 nativo do SQLite,
> 0 dep, bom p/ "SAC"/"IOF"/"Price"); (b) `lexical_weights` do bge-m3 +
> `compute_lexical_matching_score`. FTS5 e mais simples e ja no `.db`; usar FTS5 como o
> componente esparso e RRF p/ fundir com o denso.

`.projetos/<slug>/livro/.index/{corpus.jsonl, vectors.db, images/}`. Tudo gitignored
(`.projetos/`). Sound: 1 `.db` (dense+sparse), jsonl legivel p/ debug, imagens referenciadas
por path relativo ao `.index/`.

# embed da query (bge-m3 local, ~1 frase = barato), KNN + FTS5 + RRF, imprime JSON por linha.

### Anti-Patterns to Avoid

- **Reescrever `converte_livro.py` do zero.** D-14: ESTENDER. Preservar lotes/blindagem/lint.
- **Instalar olmOCR como fallback default.** vLLM nao roda nativo no Windows CPU (Pitfall 2).

- **`use_fp16=True` no bge-m3 em CPU.** Quebra/lentidao -- usar `use_fp16=False` [CITED: HF].

## Common Pitfalls

### Pitfall 1: venv com Python incompativel com MinerU (BLOQUEANTE)
**What:** `.venv-pdf` atual roda Python **3.14.3**; `pip install mineru` falha
(`No matching distribution found for mineru`) -- reproduzido nesta sessao.
**Why:** MinerU no Windows so suporta Python **3.10-3.12** (dep `ray`) [CITED: pypi].
**Avoid:** Recriar o venv com `py -3.12 -m venv .venv-pdf`. Documentar o pin no
`requirements-pdf.txt` / skill / pre-aviso.
**Warning signs:** "No matching distribution found for mineru"; `ray` import error.

### Pitfall 2: olmOCR (D-01 fallback) impraticavel no alvo free/Windows/CPU
**What:** olmOCR depende de **vLLM** (sem suporte nativo Windows; GPU-oriented; modelo 7B,
8-12GB VRAM) [CITED: docs.vllm.ai; github.com/allenai/olmocr].
**Why:** O alvo e CPU/Windows/free. vLLM exige WSL/GPU.
**Avoid:** Manter a DECISAO D-01 (fallback p/ pagina muito escaneada), mas IMPLEMENTAR o
fallback como **backend VLM do MinerU** (`MinerU2.5-Pro-...-1.2B`, ~1.2B, roda local) e, em
ultimo caso, confiar na **imagem-de-pagina** (D-02). Documentar olmOCR como "so GPU/WSL".
**[FLAG ao planner/usuario]:** trocar o ATOR do fallback (olmOCR -> MinerU-VLM/imagem) sem
mudar a INTENCAO de D-01. Confirmar com o usuario se aceitar.
**Warning signs:** tentar `pip install olmocr` e cair em vllm/torch+cuda no Windows.

### Pitfall 3: std::bad_alloc / OOM (precedente real Phase 7)
**What:** Modelos de OCR/layout estouram memoria em livro grande (a "capa virou 0101...").
**Why:** BLAS/OMP multi-thread + documento inteiro.
**Avoid:** PRESERVAR os env guards (=1) E processar em LOTES (`page_range`/batch) com
`gc.collect()` entre lotes (ja no script). MinerU pipeline CPU pede ~4GB; medir.
**Warning signs:** processo morto no meio; `std::bad_alloc`.

### Pitfall 4: 1a execucao baixa multi-GB de modelos (silencio longo)
**What:** MinerU (~1-2 GB pipeline) + bge-m3 (~2.3 GB) baixam na 1a rodada.
**Why:** Download lazy de HF/ModelScope.
**Avoid:** D-15: AVISAR antes (demora/0-token/progresso). Cachear em local compartilhado
(`HF_HOME`/`MINERU_MODEL_SOURCE` + dir de cache) e reusar entre projetos. Se HF bloquear,
`MINERU_MODEL_SOURCE=modelscope`.
**Warning signs:** 1a rodada "travada" com trafego p/ huggingface.co.

### Pitfall 5: load_extension/FTS5 ausentes em OUTRA maquina
**What:** sqlite-vec precisa de `enable_load_extension`; FTS5 precisa estar compilado.
**Why:** Em algumas builds (macOS de fabrica, Python antigo no Windows) a `sqlite3` bundled
nao habilita extensoes. **Nesta maquina esta OK** (Python 3.14, SQLite 3.50.4) [VERIFIED].
**Avoid:** No `consulta_livro.py`/indexador, fazer um **preflight**: testar
`enable_load_extension` + FTS5 e, se faltar, instruir `pip install pysqlite3-binary` (fallback
documentado por sqlite-vec). Manter o pin de Python 3.12 (que tambem traz SQLite recente).
**Warning signs:** `AttributeError: enable_load_extension` ou `no such module: fts5`.

### Pitfall 6: ColPali-first em escaneado (por que esta DEFERIDO)
**What:** Tentar retrieval visual puro (ColPali/ColQwen) como caminho primario.
**Why:** Sem fine-tuning no proprio corpus, OCR bom **recupera melhor** que visual puro em
documento degradado, e o visual ainda exige 2o passo de leitura por VLM e query mais lenta
[CITED: "Lost in OCR Translation?", arXiv 2505.05666; repo lanl/lost-ocr].
**Avoid:** Backbone = OCR-esperto (MinerU) + imagem como rede. ColPali so na Fatia 4, se o
golden set reprovar (D-16).
**Warning signs:** recall pior que o caminho LaTeX no golden set.

### Pitfall 7: API Python interna do MinerU instavel entre versoes
**What:** Em 3.x o MinerU virou orquestrador sobre `mineru-api`; imports internos
(`doc_analyze_streaming`, `union_make`) podem mudar.
**Why:** So o CLI/HTTP e contrato estavel; a API interna nao tem garantia.
**Avoid:** Encapsular a extracao atras de UMA funcao; ter o caminho `subprocess mineru -p ... -o
... -b pipeline` + leitura de `*_content_list.json` como fallback estavel. Pin de versao.
**Warning signs:** ImportError apos upgrade de `mineru`.

### Pitfall 8: lentidao em CPU em livro inteiro
**What:** Indexar centenas de paginas em CPU demora (aceitavel offline, mas pode assustar).
**Why:** OCR/VLM + embeddings em CPU.
**Avoid:** Expor progresso ("pagina N de M" ja existe); medir no golden set; backend
`pipeline` (mais rapido) por padrao, VLM so por pagina ruim.
**Warning signs:** rodada de horas sem feedback.
