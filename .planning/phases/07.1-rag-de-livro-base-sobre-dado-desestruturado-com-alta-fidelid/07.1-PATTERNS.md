## Pattern Assignments

### `scripts/converte_livro.py` (engine, ESTENDER -- D-01..D-08)

**Analogo:** ele mesmo. **NAO reescrever** (anti-pattern explicito do research). Preservar
lotes + blindagem + lint; trocar o renderer e adicionar a geracao do `.index/`.

**O QUE PRESERVAR (contrato Phase 7, nao tocar):**

- **Blindagem de memoria** (linhas 41-45) -- env guards setados ANTES de qualquer import
  pesado. MinerU/torch/bge-m3 entram no MESMO padrao (D-14, Pitfall 3):
  ```python
  os.environ["OMP_NUM_THREADS"] = "1"
  os.environ["OPENBLAS_NUM_THREADS"] = "1"
  os.environ["MKL_NUM_THREADS"] = "1"
  os.environ["VECLIB_MAXIMUM_THREADS"] = "1"
  os.environ["NUMEXPR_NUM_THREADS"] = "1"
  ```
  Acrescentar (research Pattern 1): `os.environ.setdefault("MINERU_MODEL_SOURCE", "huggingface")`.

- **Imports lazy** (comentario linhas 47-48; pratica em `convert_pdf` linhas 227-235) -- o modulo
  importa SEM docling no topo, para a suite de logica rodar sem deps. MinerU/FlagEmbedding/
  sqlite_vec DEVEM seguir o mesmo: import dentro da funcao, nunca no nivel de modulo.

- **Conversao em lotes anti-`std::bad_alloc`** (`convert_pdf`, linhas 212-269) -- contagem por
  `PdfReader`, loop por lote com `gc.collect()` entre eles. O MinerU em lotes herda essa forma
  (research Pattern 1: `page_range` / `gc.collect`):
  ```python
  total_pages = len(PdfReader(pdf_path).pages)
  batches = _page_batches(total_pages, batch_size)
  for i, (start, end) in enumerate(batches, 1):
      result = converter.convert(pdf_path, page_range=(start, end))
      docs.append(result.document)
      gc.collect()  # Fallback de OOM (Pitfall 1)
  ```
  `_page_batches()` (linhas 171-191) e `_ChainedDoc` (linhas 194-209) sao PUROS e ja testados
  -- reusar como estao.

- **`sanitize_slug`** (linhas 50-62) -- path-safety ASVS V5 ANTES de qualquer write. Reusar
  identico em `consulta_livro.py` (mesma regex `^[a-z0-9-]+$`).

- **`markdownlint --fix`** (`_run_markdownlint`, linhas 272-288) -- lista de args FIXA + path
  controlado, `shell=True` no Windows, skip gracioso no `FileNotFoundError`. PRESERVAR no
  markdown legivel (D-14).

- **Histograma de heading** (`heading_histogram`, linhas 155-165) -- ja impresso para escolher
  `--cut-level`. E a base do corte por fronteira real (D-04, research Pattern 2): estender para
  ler labels/bbox do MinerU em vez de `DocItemLabel` do docling.

**O QUE TROCAR/ADICIONAR:**

- **D-03 (causa-raiz das "0 formulas"):** o renderer atual (`render_chapter`, linhas 120-140 e
  o loop interno) so concatena `item.text`; itens de `equation` sem `.text` legivel sao
  perdidos. Trocar para emitir LaTeX como `$$...$$` (research Code Example 2):
  ```python
  def render_block(b):
      if b["type"] == "equation": return f"$$\n{b['text']}\n$$"
      if b["type"] == "text":     return b["text"]
      if b["type"] == "image":    return f"![]({b['img_path']})"
      return ""
  ```

- **D-04 fronteira real:** evoluir `_is_boundary` (linhas 79-87) / `split_into_chapters`
  (linhas 89-117) para cortar so em `type=="title"` OU heading com fonte >= percentil do
  histograma (research Pattern 2 `is_chapter_boundary`) -- ABANDONAR "1 arquivo por heading".

- **D-05 chunking parent-child + provenance:** NOVO bloco deterministico sobre
  `content_list.json` (research Pattern 3 `build_chunks`). A ancora `<!-- page: N -->`
  (renderizada em `render_chapter` linhas 128-130 a partir de `_page_of`, linhas 71-77) VIRA o
  campo `page` do provenance: `"page": child["page_idx"] + 1`.

- **D-08 geracao do `.index/`:** NOVO -- grava `corpus.jsonl` + `vectors.db` (vec0 + FTS5) +
  `images/` em `.projetos/<slug>/livro/.index/` (research Pattern 4 e 5).

- **D-01 fallback:** MinerU pipeline (CPU) por padrao; backend VLM-1.2B do MinerU por pagina
  ruim; imagem-de-pagina como rede final (NAO olmOCR -- Pitfall 2, A5 resolvido).

> **Encapsular a extracao MinerU atras de UMA funcao** com fallback CLI->artefatos
> (`mineru -p ... -o ... -b pipeline` + leitura de `*_content_list.json`), porque a API Python
> interna do MinerU e instavel entre minors (Pitfall 7).
